## Iterations

Record each material issue, its code correction, and the capture that confirms
the correction. Keep failed captures distinguishable from final evidence.

## Checks and limits

List test commands/results and actual native journeys. Separate framework or
automation limitations, untested platforms/devices, unrelated existing test
failures, and work still required. Never mark a state verified from compilation
or from a capture that shows a different screen.
